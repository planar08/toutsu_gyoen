# 東津御苑｜原官網主機版線上訂房系統

本版本放在您自己的網站主機，使用您原有網域。沒有 ChatGPT 網站連結、ChatGPT 登入、Sites、Cloudflare D1 或外部訂房後端依賴。


重要：解壓縮後直接雙擊 index.html，只能查看官網版面。網址若以 file:/// 開頭，無法執行PHP後端、登入或保存訂單；需先上傳至支援PHP/PDO_SQLITE與HTTPS的主機，再以正式網站網址開啟。

## 主機需求

- PHP 8.1 以上，建議使用主機商仍提供安全更新的版本。
- PHP 的 PDO_SQLITE 擴充套件。一般虛擬主機可由控制台或請主機商啟用。
- HTTPS 安全連線。
- `private/storage` 可供 PHP 程式讀寫，建議權限 0700 或依主機商指示使用0750；請勿設為0777。
- 可將 `private` 放在網站公開目錄外。如果只能上傳靜態HTML、沒有PHP執行環境，單純替換檔案無法運作，需要主機商提供PHP主機。
- 不需要 MySQL、Node.js、Composer、npm、會員登入或外部帳號。

## 一、先備份

先下載備份原官網首頁與照片。這份套件含原官網首頁及49張照片，已加入同站訂房、訂單查詢與管理入口。
本次不會連線修改您的原官網主機；請您手動上傳。也不會自動匯入先前其他主機或系統的訂單。

## 二、上傳檔案（請注意這兩個位置不同）

壓縮檔包含：

- `public_html/`：公開的官網頁面、49張照片、`booking/`、`admin/`、`assets/`。
- `private/`：PHP後端設定、首次安裝碼、資料庫與登入工作階段；必須在網站公開目錄外。
- `tests/`：離線測試程式，無須上傳。
- 本安裝說明：無須上傳至公開網站。

以常見的 `/home/帳號/public_html/` 為例：

1. 將套件中 `public_html/` **裡面的全部檔案** 上傳至原官網的 `/home/帳號/public_html/`。不要多套一層 public_html。
2. 將套件的 `private/` 上傳至 `/home/帳號/private/`，與 public_html 同一層。
3. `private` 不能放入 public_html，也不能放在其他網域會公開提供檔案的目錄內。
4. 如主機的公開目錄名稱是 `www` 或 `htdocs`，做法相同：公開檔案放進該目錄，private 放在它外面並同一層。
5. 若主機要求其他私有路徑，請請主機商協助調整 `public_html/booking/api.php` 最前面的 `require`，指向正確的 `private/bootstrap.php`。
6. 如原官網有自訂 `.htaccess`，請保留原規則，再合併此套件中的目錄首頁與安全標頭設定。若 Apache 禁止 `Options -Indexes` 而出現500錯誤，可請主機商停用此單行規則。
7. 網域根目錄應指向 public_html，不能指向包含 private 的上層。若首頁優先開啟舊的 index.php，請調整 DirectoryIndex 或由主機商設定使用本版 index.html。

所有網站連結使用相對路徑，不必填入 ChatGPT 網址。此套件按「官網根目錄」安裝；若要安裝於子目錄，請由主機商指定真正公開目錄外的 private 路徑。

## 三、首次安裝後台

1. 上傳完成後，用 HTTPS 開啟您原官網的 `/admin/install.html`。
2. 用文字編輯器在本機開啟套件的 `private/setup.key`，複製裡面的安裝碼；這不是管理密碼。
3. 在安裝頁填入安裝碼，設定管理帳號及您自己的密碼。建議帳號 `planar08`，也可自行修改；帳號可用英數字與 @ . _ -。
4. 密碼至少12個字元；建議使用12至128個英數字與符號。不要使用Email或其他網站的既有密碼。
5. 成功後，安裝入口即關閉，主機上的 setup.key 會嘗試自動刪除，即使刪除失敗也無法再重建帳號。
6. 開啟原官網的 `/admin/`，用剛設定的網站帳號與密碼登入。

若畫面顯示 PDO_SQLITE、HTTPS、private路徑或資料目錄錯誤，請依畫面訊息請主機商協助。若網站位於反向代理後方，請主機商正確設定 PHP 的 HTTPS 伺服器變數；不要為正式網站關閉 `require_https`。
安裝碼等同首次建置權限，請勿公開或轉交非管理人員；安裝完成後請妥善保管完整套件。

## 四、使用網址（全部在您的原網域）

- 官網首頁：原網址的 `/index.html`。
- 旅客訂房：原網址的 `/booking/`，免登入。
- 旅客查單：原網址的 `/booking/#lookup`，輸入訂單編號與專屬查詢碼。
- 管理後台：原網址的 `/admin/`，獨立帳號密碼登入。

首頁主選單、首頁主圖、每間房型、聯絡區及右下角都已加入訂房連結。每間房型連結會帶入對應房號。

## 五、訂房與房況管理

- 九間客房：101、102、103、104、105、201、202、203、204。
- 旅客選擇日期、房型、早餐與加床，填寫資料後送出申請。
- 訂單永久保存在您主機的 SQLite 資料庫，不使用瀏覽器localStorage保存訂單。
- 待確認申請不保留房間。民宿檢查所有平台房況與入住條件後，可在後台確認訂單並鎖定本站房間。
- 同房同晚不可確認兩筆訂單，日期衝突時整筆回滾。
- 取消訂單會釋出本站房間；退款與旅客通知需另行處理。
- 電話／外部平台訂房或維修可逐日逐房「手動關房」。
- 後台可依狀態篩選、查看最近500筆訂單、匯出CSV、設定特殊日期價格及修改密碼。
- 遊客訂單查詢不會顯示姓名、電話、電子郵件或備註，查詢碼只存雜湊，請旅客下載保存憑證。

## 六、費用規則

房價依您原網站設定。週日至週四預設平日，週五、週六預設假日。
寒暑假請在後台逐日設為假日；過年與迎王期間請設為定價。未設定的特殊日期僅提供基礎試算，最終以民宿確認報價為準。
早餐每人每晚100元，加床每床每晚600元且不含早餐。11歲以下不佔床免費。
可加床房每筆先接受1床申請，實際名額與含孩童總入住人數仍需由民宿確認；102、105、202、203不可加床。
入住15:00、退房11:00，全室禁煙、不可攜帶寵物。

## 七、資料保護、備份與日後更新

- 資料庫：`private/storage/booking.sqlite`。請定期由主機備份工具在低流量時備份，或請主機商使用 SQLite 一致性備份功能。
- 登入資料：`private/storage/sessions/`，不可公開下載。
- 使用 PHP 的 password_hash/password_verify 儲存驗證密碼；有Argon2id時優先使用。
- 管理工作階段閒置30分鐘或最長8小時後到期；登出及修改密碼會撤銷管理權限。
- 所有修改請求檢查CSRF，並有限制登入／送單／查單次數。
- **日後更新程式時不可用空資料庫覆蓋 private/storage，也不要重新上傳setup.key來覆蓋既有安裝狀態。** 本套件尚無訂單、尚無管理帳號，第一次使用須完成安裝。
- 遺失密碼時，可由有主機終端機權限的擁有者執行 `php private/reset-admin.php`，依提示重新產生安裝碼，保留訂單並撤銷既有登入；再從安裝頁重建管理帳號。沒有終端機權限請洽主機商。
- 因應個資更正、刪除或保存期限需求，請由民宿依實際政策受理；本版不自動清除旅客資料。

## 八、目前功能範圍

這是需要民宿人工確認的訂房申請系統，不是即時付款或自動確定住房系統。
尚未串接 Booking.com、Agoda 或 Channel Manager；外部平台庫存需人工同步。
尚未加入線上金流、訂金、退款、發票、自動Email或LINE通知，管理者需要主動查看後台並聯絡旅客。
若需遷移原系統正式訂單，請先另行匯入及核對，再開放收單，避免跨系統重複訂房。
